# AI 活用ログテンプレート

> 対象: 全体（開発フェーズで全員が使用）／ 所要時間: 1 件あたり 1〜2 分／ 前提: なし

## この資料で分かること

- AI を使った作業を 1 件ずつ記録するログの書き方
- 必須列だけでも記録を続けられる、負荷の低い運用方法
- 「採用」だけでなく「不採用」だった記録例

## なぜ必要か

このログは、**自分の振り返りと学びの蓄積**のためのものです。書き溜めていくと、
「どんな指示が効いたか」「どんな失敗が繰り返されるか」が自分の記録から見えてきます。
記録のない作業は、後から振り返ることができません。

指標の算出方法（採用率の集計単位など）はこのテンプレートでは定義しません。
集計・KPI としての使い方は [KPI 設定テンプレート](04_kpi-template.md) にまとめてあるので、
そちらを参照してください。**本テンプレートの役割は 1 件ずつの生ログ記録に専念すること**です。

## テンプレート

作業ごとに、以下の項目を記録します。**必須列（★）だけでもよい**です。時間がなければ
★の 5 項目だけ埋めて次の作業に進みましょう。

| 種別 | 項目 | 内容 |
|------|------|------|
| ★必須 | 日付 | 作業日 |
| ★必須 | 工程 | 設計／実装／テスト／レビュー／文書化 のいずれか |
| ★必須 | ツール | 自分が使っている AI ツール（例: Claude、Claude Code、GitHub Copilot 等） |
| ★必須 | タスク概要 | 何を依頼したか（1〜2 行） |
| ★必須 | 採用状況 | そのまま採用／修正して採用／不採用 |
| 任意 | プロンプトの要点 | 再利用可能な形での指示の骨子（**機密情報を含めない**） |
| 任意 | 手戻り・誤り | AI 出力の誤り、もっともらしい推測、検証で発覚した問題（なければ「なし」） |
| 任意 | 所要時間 | AI ありの実測時間／AI なしの場合の見積時間 |
| 任意 | 学び | 効いた工夫、失敗パターン、次に試すこと |

## 記入例

「修正して採用」と「不採用」の 2 パターンを載せます。不採用も正直に記録してよい記録です。

| 項目 | 例 1: 修正して採用 | 例 2: 不採用 |
|------|--------------------|--------------|
| 日付 | 2026-08-05 | 2026-08-06 |
| 工程 | 実装 | 実装 |
| ツール | Claude Code | Claude Code |
| タスク概要 | FAQ 検索 API の部分一致検索と入力検証の追加 | クイズの採点結果を集計するバッチ処理の実装 |
| 採用状況 | 修正して採用 | 不採用 |
| プロンプトの要点 | 目的＋既存実装の踏襲元を指定＋テスト 4 ケースを完了条件に指定 | 集計ロジックを一括で依頼 |
| 手戻り・誤り | 依頼していない共通コンポーネントの変更が混ざっていた → 差分レビューで検出し差し戻し | 集計対象の期間の境界（月初・月末）の扱いが要件と食い違っていた。説明を尽くしても解消しなかったため自分で実装し直した |
| 所要時間 | AI あり 40 分／見積（AI なし）120 分 | AI あり 30 分（不採用）＋自前実装 50 分 |
| 学び | 「変更不可ファイル」を明示したら 2 回目はスコープ逸脱なし。完了条件のテストケース列挙が有効 | 境界条件は言葉で説明せず、具体的な入出力例（表）で示した方が伝わりやすい |

## 運用ルール

- **作業のたびに記録する**（後でまとめて書くと精度が落ちる。必須列だけなら 1 件 1 分以内で書ける粒度でよい）
- プロンプト欄に**実データ・個人情報・認証情報を書かない**（ログ自体も共有される前提で書く。
  詳しい取り扱いの基準は [運営ルール](../00_common/03_ground-rules.md) を参照）
- 記録場所は、リポジトリ内の Markdown ログ・GitHub Discussions 等、自分（チーム）で決めた場所を使う
- 「AI なしの見積時間」は主観でよいが、根拠（過去の類似作業）を書けるとなおよい
- 集計方法・指標の定義は書かない。[KPI 設定テンプレート](04_kpi-template.md) を参照する

## やってみよう

直近の AI を使った作業を 1 件、必須列だけで記録してみましょう。
